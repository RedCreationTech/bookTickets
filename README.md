# 红创 · 智慧体检一体化平台

基于《数字化健康体检一体化管理软件_技术需求清单》的纯前端交互演示。包含多角色管理后台、患者移动端 H5（微信小程序体验仿真）、体检自助机与报告打印装订机。

**本项目是可运行的合成数据演示，不是可投入医疗生产的系统，也不是招标符合性或验收证明。** 945 个核对项不等于 945 项功能完成。请查看逐项[需求覆盖矩阵](docs/coverage-matrix.md)及[模拟和验收边界](docs/BOUNDARIES.md)。 各模块统计与本次补齐口径见[交付范围](docs/DELIVERY_SCOPE.md)，实测结果见[验证报告](docs/TEST_REPORT.md)。

## 启动

要求 Node.js 24 LTS、npm 11（本次验证环境版本：Node 24.19.0）。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。无需账号、后端、数据库、API Key。默认管理员工作台。右上角可切换 8 种角色与院区，上方可切换患者与自助机。初次加载的所有客户、单位、报告、身份均为人工合成。

```sh
npm run check          # ESLint + TypeScript + Vitest/jsdom + 生产构建
npm run build
npm run preview        # 预览 dist 构建
python3 scripts/coverage.py --check
npx playwright install chromium
npm run test:e2e       # Chromium 桌面与移动视口测试
```

如需同一局域网的手机扫码体验，可由开发者在可信测试网络使用 `npm run dev -- --host 0.0.0.0`，并通过本机局域网地址打开。二维码使用当前页面来源地址生成；127.0.0.1 地址不能从另一台手机访问。此操作不会发布到互联网。

## 十分钟演示闭环

1. 患者端打开“开启健康计划”，查看套餐对比或个性化问卷，选择体检人、院区、日期与套餐，阅读须知后确认预约。
2. 对新订单完成“模拟支付”。订单会立即出现在后台预约列表；不会扣款。
3. 打开体检自助机，选“自助签到”，用同一合成身份核验，选择订单并确认到检。可更改到检院区。
4. 分检工作站先选择与订单一致的业务日期，再定位该客户与允许科室，填入正常示例或手动编辑；数值/描述项目按实际配置校验。异常样例需复核与小结，提交后出现全局处置提醒，可选择是否进入随访。
5. 总检工作站依次通过初审、主检、总检，或填写原因驳回。需要结论且检查结果完整。重复同次确认不能跳过审核层级。
6. 报告中心勾选已审核报告，展开“真实PDF生成与报告版式”，生成和下载内嵌中文字体的PDF；历史对比只选择当前浏览器存储的往期订单。报告机模拟打印/装订；档案流转分别登记打印、装订、交接、入出库与领取，故障时不登记完成。
7. 健康管理师在干预随访录入本次结果再完成任务；患者端可看报告，企业端展示合成汇总。
8. 质控与追踪查看各环节的时间、角色、对象及前后变化。点击上方“重置演示”可恢复样例。

操作引导：左下“演示指南”内有36秒静音教学短片、中文字幕与章节定位。它是原创流程示意，不是实际UI录屏或测试截图。

## 数据与权限

- 共享状态存储在当前浏览器 `localStorage`，同源标签页同步；刷新不丢失。换浏览器/域名/设备不会自动共享。
- 可通过“重置演示”清除本地数据。浏览器禁用存储或配额耗尽时，不能保证持久化。
- 当前支持管理员、前台、分检医生、总检医生、健康管理师、财务、企业 HR、客服。导航与直接访问都演示角色路由限制。
- **所有角色权限和身份均可在浏览器中修改，不是安全边界。** 真实鉴权、医院/企业多租户数据隔离、审计防篡改必须由服务端实现。
- 不要输入真实身份证、病历、电话、用药、支付或其他个人数据。CSV 导入只接受合成标识。导出文本采取表格公式转义。

## 清楚区分演示与真实能力

- 支付/退款/余额/发票、短信/电话/邮件/微信通知都只改变本地状态。
- 无医院 HIS、LIS、PACS、医保、税务、微信、物流、读卡器、人脸、打印/装订或其他设备接口；二维码能编码本地入口，但不代表微信原生小程序已发布。
- 医学指标、评估、风险、AI 与关联结论是有限规则或固定合成样例，不符合完整专家共识知识库，不可用于临床诊断与治疗。
- 报告提供HTML预览、真正的本地中文PDF生成/合并/下载、文本与团检可编辑Word导出；没有服务端报告引擎或实机打印回执。
- 部分宽范围后台条款为参数化记录/配置演示，未完整实现其生产业务算法。逐项状态见覆盖矩阵。
- 吞吐量、响应时间、并发、网络可靠性、数据库备份、密码学、信创、等级保护、硬件参数、售后与实施承诺不能在这个项目里验收。

## 验证证据

见 [测试报告](docs/TEST_REPORT.md)。jsdom 交互通过不等于真实 Chromium、移动设备或视觉截图验收通过。本地工作区的浏览器连接受限；独立 GitHub Actions Chromium 环境已实际运行红创快照桌面/手机 E2E（17通过、1移动重复角色检查跳过）并产生24张已检查截图，见[红创快照证据](https://github.com/RedCreationTech/bookTickets/actions/runs/38333647742)。当前版本结果以对应提交的 Actions run 与测试报告为准，不把旧快照验证外推到后续改动。

## 专项交互入口

- 预约与登记的“项目与套餐规则”：维护共享套餐目录，设置性别/年龄/单位适用、互斥/依赖/必检与禁折；新建预约展开多套餐与单项计费，核对去重、总价反算和分行优惠。规则是合成业务规则，不构成医学适应证。
- “团检订单与预算”：创建单位订单、固定/限额/无限额、自选包与人员分组；开单带出组套餐，单位与个人按预算分摊；预付款账本不允许透支或重复结算。
- “手工客户登记”：仅接受 DEMO 标识，维护证件类型、客户类型和订单/导检区域映射；订单详情可以维护基本资料、办理未到检替检并双向追踪。
- “打印任务与版式”：预览导检/项目/条码任务，配置照片与表头、批量生成，演练失败重试；“改日检到期管理”需先登记改日检，再预览和明确确认批处理。
- 分检扩展：分级小结排序、本地图片/音频文件、结构化问诊、申请单模拟重推；Ctrl/⌘+Enter 复用提交校验；未进入审核的结果可留痕撤销。
- 总检扩展：按日期排班、实际分配负载、演示权重、人工阳性、词条映射、建议排序、特殊复查；报告扩展提供安全 JSON 模板导入和真实数据预览、解读与回收工作量。
- 服务与质控中心：单位排期日历、容量/时段/模拟放号、门户发布字段、通知模板；设置中的自定义角色可实际限制菜单、路由、患者/院区和体检类型。退出按钮始终保留。
- 健康管理与商城：不同合成问卷计分、模板快照生成计划与任务、稳定指标人群分析；健康豆独立账本、兑换核销、活动容量；商品预约、成团、地区重量运费、消费码去重核销。

以上均以本地演示状态执行，仍需结合逐项矩阵的未完成部分、外部依赖和临床/设备验收边界使用。

## 品牌与数据升级

演示品牌统一为“红创”。读取旧版浏览器数据时，会保留订单、金额、客户、任务、个人编辑与技术ID，并迁移可读品牌文字到新版存储；旧版存储作为原样备份保留。迁移只记录一次说明性日志，不使用清空数据作为升级方式。

## 本次收口交互

- 患者“查看消息”：五维必答满意度，每订单独立评价、防重复提交并可刷新回看。
- 项目规则与团检订单：配置套餐 N 选 M；H5 与登记页实际消费规则并对重复项目去重计费。
- 导检队列：候检人数上下限过滤、解释型瓶颈阈值；暂停生成唯一二维码凭条，输入模拟编号恢复原队列，一次核销。
- 门户编辑：512KB以内 PNG/JPEG/WebP 海报预览发布、安全 HTTPS 外链配置；患者门户消费已发布内容。
- 分检界面：展示登记身份抽象双图及人工核验状态；报告工作量中的导检回收支持手选/模拟码并提示未检项目。
- 财务“订单支付明细与分组结算小计”：单位/日期/人员组筛选、套餐/加项/弃检/自费明细和小计导出。缺失定价或收款记录显示“未登记”，不凭状态编造金额。

## 扩展条款体验

本批固定核对范围见 [22项扩展清单](docs/EXTENSION_SCOPE.md)，逐项状态仍以 [覆盖矩阵](docs/coverage-matrix.md) 为准。

- H5预约：按部位/疾病筛选加项，切换院区查看套餐；多套餐自动过滤重复/互斥并同步计价，双必检冲突会阻止提交。各套餐可配置独立自选包。
- 团检：配置员工/亲属折扣、亲属专属套餐及个人/单位承担；使用另一名合成亲属预约，实际套用权益。取消可保留取消记录或将目标业务记录归档；恢复仅供历史查询，不重启预约或重新收费。
- 订单详情：弃拍及多类型合成签署需明确确认，关闭不留样、重复提交不重复记录；不会据签署跳过检查或审核。登记自定义合成既往史后，分检会展示对应医生阅读提醒。
- 财务：在交易关联发票台账生成发票，再进入到期提醒设置账期、选择业务员并推进演示日期；按同一发票登记本地回款，已全额回款/作废不再提示。
- 企业健康：科研复合筛选支持 AND/OR、血脂/血压等指标组合。缺失数据标为未知，导出与当前结果一致，不作为医学研究结论。
- 导检：演示时钟消费排队启停计划，查看重点科室进度，设置固定超声号、合成姓名模拟读音；导检专用用户可分配队列、停用并查看本地在线医生会话。
- 通知与专项质控的“事件与祝福”：根据驳回、报告超期、演示生日/节日生成去重的本地通知，可设为已读。只在页面运行及显式推进时钟时执行，没有后台调度或外发短信。

## 扩展工作区演示入口

- 预约与开单：单位人员分组、同单位不同订单独立排期、套餐/项目容量、三种合成身份CSV校验、批量项目变更及折扣申请审批；收费可按项目、渠道、部分收退和会员卡演练。旧快捷加项进入受校验工作台，克隆预约先预填再确认。
- 分检：可维护父项/报告子项映射、数字及描述字典、正常/危急范围；按授权科室过滤。声音录制使用明确标注的合成静音WAV，可开始/暂停/保存/取消，不请求麦克风。采血、尿、粪、碳呼吸、妇科、病理工作站有可编码CODE128和按单项目映射、合并、打印/采集记录。
- 审核：可关闭初审形成主检→总检两节点，已有订单保留节点快照；医生等级约束报告难度，撤销权限可配置，主检退回所选分检项目会清除相应子结果，总检可退回主检。
- 报告：支持按姓名、体检号、合成证件、单位、实际主检医生和日期查询。柜位用稳定ID管理，批量流转先预览并校验容量/版本；发放记录领取人、操作人、时间和方式。团检只纳入符合条件的已完成实际本地订单，保存不可变人群快照并导出DOCX及阳性/结论CSV。
- 健康运营：家庭成员与机构/专家使用ID关系，随访支持负载预览和自动分配，服务计划/评估模板实际消费，商城退换货与库存、余额和订单逐笔收退款联动。所有消息只进入本地记录。
- `docs/FRONTEND_COMPLETION_AUDIT.json` 保留9014阶段778软件原子项审计；本轮逐项核对见 `docs/FRONTEND_COMPLETION_REVIEW.md`，各领域行为证据见 `docs/completion-*.json`。这些文件不能代替后端、医院/微信接口、硬件、医学规则与生产安全验收。
