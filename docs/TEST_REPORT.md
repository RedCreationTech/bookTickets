## 证据范围

本报告区分状态机、React DOM 交互、实际浏览器和外部系统。Vitest 使用 jsdom，会真实触发 React 组件和本地存储，但不执行 Chromium 排版，也不是医院验收。

- ESLint：执行源码静态检查。
- TypeScript：严格模式类型检查；记录型后台数据允许扩展字段。
- Vitest：覆盖预约、支付确认/取消、重复提交、到检、临床数值校验、锁定、全局异常处置、三级审核、驳回、模拟打印/装订/缺纸/离线/超时、随访结果、角色路径拦截、CSV名单校验、库存与客服工作流、历史缺值、结构化审计、排队调序/过号召回、日容量/周末规则、存储恢复等。
- 生产构建：生成按场景懒加载的静态产物；覆盖矩阵较大并产生体积警告，未作为性能验收证明。
- 945项结构审计：原文/页码/ID/原条款/星标数量、证据与测试锚点、JSON/CSV/Markdown一致性；不意味着945项交互通过。
- 教学短片：本地生成的36秒1280×720 H.264流程示意，`ffprobe`验证媒体信息并人工查看封面像素；不是应用录屏或浏览器截图。

## 尚未验证

- 当前环境拒绝启动独立Chromium进程所需通信，受支持的云端浏览器也无法访问本地预览服务。没有绕过限制或公开部署。
- 本地限制没有阻止使用独立CI真实Chromium。已取得并检查红创快照的24张截图，涵盖8种角色、患者、自助机、报告机、大屏和完整跨端闭环。移动Chromium模拟视口不等于实机触摸、扫码或无障碍完整验收。
- `e2e/health-demo.spec.ts`提供桌面与移动Chromium项目。当前源码增加的测试必须在对应提交的Actions实际运行成功后计入，不从测试源码存在推定通过。
- 未验证实体设备、微信原生小程序、真实扫码、支付/退款/发票、短信/呼叫中心、HIS/LIS/PACS接口、临床规则有效性、多用户并发、性能、安全和容灾。
- 没有执行945项手工验收。矩阵引用自动测试时，只证明所列断言子集。

## 复现

```sh
npm ci
npm run check
python3 scripts/coverage.py --check
npx playwright install chromium
npm run test:e2e
```

业务日期在Vitest中固定为工作日，设备计时器由用例控制，因此测试时长不是硬件性能数据。真实E2E采用独立浏览器上下文和合成数据，测试会重置本地演示状态。
