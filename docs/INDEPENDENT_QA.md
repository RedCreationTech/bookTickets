## 已实际执行的独立回归

- 患者端预约与支付关闭/确认 → 自助机身份模拟与签到 → 分检录入 → 初审、主检、总检 → 报告机模拟打印和装订 → 随访结果必填及完成 → 返回患者端查看报告。
- 各阶段卸载并重新挂载页面，核验通过 localStorage 恢复共享订单、结果、打印计数及随访状态；这是刷新持久化的 DOM 层替代验证。
- 取消前保留预约、确认取消后不再进入自助签到订单；取消保留历史状态。
- 患者端提交的随访申请出现在后台「待处理」看板。
- 七个非管理员角色各自尝试一个无权访问的页面，得到前端拒绝页和对应工作台入口。
- 使用 StorageEvent 模拟同源另一标签页变更，验证当前页面同步。本项未验证真实多标签页的并发写入。
- 锁定订单不能保存临床结果或生成新的异常上报；锁定的待签到订单不能误显示签到成功。
- 异常结果的确认及小结不能为空；切换患者后清除上一患者确认及小结；真实组件提交合成异常后产生全局处理弹窗。
- 重大异常处理保存方式、结果、处理人、时间；可选择创建或不创建随访，重载后保持已处理状态。
- H5 单次确认重复激活不重复建单；同一初审确认重复激活不跨越两个审核阶段。
- 自助机默认保留订单原院区，显式更换院区后记录正确。
- 20 个后台、患者、自助机路由分别进行 DOM 挂载冒烟，均显示页面主标题。
- 从预约页实际入口打开团检 CSV 导入，填入合成示例、校验、确认并创建预约，重载后仍显示；从侧栏打开工作量统计并查看结构化变更前后值。

测试中的日期固定为工作日，避免新加入的周末禁约策略令测试随运行日期变化。报告机计时器在测试中受控推进，不代表真实设备耗时或性能。

## 本轮发现并修复后回归的问题

1. H5、工作台和自助机院区名称不一致，签到可能静默覆盖院区。
2. H5 任务使用 `pending`，未进入中文状态的后台随访看板。
3. 异常复核未强制填写小结，且患者切换可能继承前一患者确认。
4. 锁定分检订单虽拒绝保存结果，仍错误创建异常记录并提示成功。
5. 连续激活同一初审按钮会跳过两个审核阶段。
6. 连续激活 H5 预约确认会创建重复订单。
7. 锁定待签到订单虽未更新状态，自助机却提示签到成功。

上述七类问题均已在最终独立用例中回归。实现期间曾出现新变量声明顺序的 TypeScript 错误及覆盖矩阵陈旧锚点，均已修正并重新检查；最新结构审计通过。
